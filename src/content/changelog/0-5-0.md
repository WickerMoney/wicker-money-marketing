Plugin platform hardening, plus account allowances. The theme is getting the
plugin foundations right before more plugins are built on them:
one shared contract for plugin server code, labelled stability for the plugin
SDK, fewer duplicate requests, a way to name the instance's owner up front,
and plainer wording about what a plugin is trusted to do. There is no breaking
change for plugin authors. **Back up your database before upgrading.** Both of
this release's database changes can be undone, so going back to 0.4.2 doesn't
need the backup, but it's still the safe habit.

### Added

- **Name your owner.** Set `BOOTSTRAP_OWNER_EMAIL` and only the account
  registered with that address becomes the instance's owner, even if someone
  else signed up first. Left unset, nothing changes: the first account is the
  owner. Email addresses aren't verified, so register your own account
  promptly, then close registration. See
  [Owners and members](https://wickermoney.dev/docs/features/owners-and-members#choosing-who-the-owner-is).
- **Account allowances.** Say "$150 a month goes into this checking account to
  spend on whatever" and see how much of it is left. Everything that leaves
  the account counts, except transfers, income and the categories you choose
  (holiday gifts, say, which keep a budget window of their own). What you
  didn't spend rolls into next month, and an overspend carries forward. See
  [Budget account allowances](https://wickermoney.dev/docs/features/budget-account-allowances).
- **One server contract for plugins.** `@wickermoney/plugin-sdk/server` holds
  the types and helpers a plugin's server code is built on, in one place
  instead of a copy in each plugin. Nothing already published changed.
- **Stability labels for the plugin SDK.** Each entry point is now marked
  stable or experimental, so plugin authors know what can change under them.
  Only the recurring-items date maths is experimental, and nothing was removed
  from it. Two calendar helpers, `addDays` and `addMonths`, are now exported
  from it, replacing the copies the app carried. See
  [Stability tiers](https://wickermoney.dev/docs/contributing/plugin-authoring#stability-tiers).

### Changed

- **Add and edit forms open in a dialog.** On Accounts, Categories and
  Recurring, "Add account", "Add category", "Add rule" and "Add recurring item"
  are buttons in the page header, so the tables get the full width. They open
  in the same dialog Transactions uses: a side drawer on a computer, a
  full-screen sheet on a phone.
- **The dashboard asks once.** Widgets that need the same numbers now share
  one request instead of each making their own, with no change to any plugin.
- **Recurring matches load faster.** The Transactions page reads the data
  behind its recurring-item matches once instead of twice, with the same
  results.
- **Plainer security wording.** The docs now say directly that a plugin's
  screens run fully trusted inside the app, and that the database role limiting
  a bundled plugin's queries is a guardrail against honest mistakes, not a
  sandbox. That is why installing third-party plugins isn't supported yet.
  Nothing about how plugins behave changed.
- **A startup warning.** A new instance with open registration and no
  `BOOTSTRAP_OWNER_EMAIL` logs a reminder that the first person to register
  becomes its owner.

### Fixed

- The search box, date pickers and buttons on the Transactions filter row now
  line up.
